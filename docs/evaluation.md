# การทดลองและการประเมินผล

## เลือกรอบที่จะรัน

| คำสั่ง | คำถามที่ใช้และผลที่ได้ |
| --- | --- |
| `thai-legal-rag run --mode pilot --retrieval-only` | เลือกคำถาม pilot ที่จับคู่มาตราได้ครบสูงสุด 40 ข้อ วัดการค้นทั้งสี่วิธี |
| `thai-legal-rag run --mode pilot` | ค้นเหมือนแถวบนและเลือกคำถามที่มีคำตอบอ้างอิงมาสร้างคำตอบสูงสุด 4 ข้อ |
| `thai-legal-rag run --mode test` | ค้นทุกข้อใน CCL test ที่จับคู่ได้ครบ และสร้างคำตอบจากชุดย่อยสูงสุด 200 ข้อ |

คำถามชุดย่อยที่ใช้สร้างคำตอบเลือกจากข้อที่มีคำตอบอ้างอิง โปรแกรมใช้ seed สลับลำดับก่อนจัดกลุ่มตามชื่อกฎหมาย แล้วเลือกตำแหน่งที่กระจายตลอดรายการ วิธีค้นทุกแบบใช้คำถามชุดเดียวกัน รหัสข้อที่ใช้จริงอยู่ใน `question_ids` และ `generation_question_ids` ของ manifest

ถ้าจะรันซ้ำเพื่อเทียบผล ให้ใช้รุ่นชุดข้อมูลและโมเดลจาก `manifest.json` เดิมกับ `--corpus-revision`, `--pilot-revision`, `--test-revision`, `--bge-revision` และ `--generator-revision` คงค่า seed จำนวนคำถาม อุปกรณ์ และรุ่นแพ็กเกจให้ใกล้เคียงกัน ดูตัวเลือกด้วย `thai-legal-rag run --help`

| ตัวเลือก | ค่าเริ่มต้น | ใช้เมื่อ |
| --- | --- | --- |
| `--pilot-questions` | 40 | จำกัดจำนวนข้อที่ใช้ค้นใน pilot |
| `--pilot-generation-questions`, `--test-generation-questions` | 4 และ 200 | จำกัดจำนวนข้อที่ใช้สร้างคำตอบตามชุดที่เลือก |
| `--seed` | 42 | กำหนดการเลือกคำถามและการฝึก Word2Vec |
| `--device` | `auto` | ใช้ CUDA ถ้ามี หรือกำหนด `cpu` หรือ `cuda` โดยตรง |
| `--bge-batch-size` | 8 | ลดจำนวนตัวบทที่ BGE-M3 อ่านพร้อมกันเมื่อหน่วยความจำไม่พอ |
| `--output-dir` | `rag_results` | เปลี่ยนตำแหน่งเก็บผล |

## อ่านคะแนนการค้น

มาตราอ้างอิงคือรายการที่ชุดข้อมูลกำกับไว้ ลองสมมติว่าคำถามมีมาตราอ้างอิง A และ B และวิธีค้นให้ลำดับ X, A, Y, B, Z

| คะแนน | อ่านอย่างไรจากตัวอย่าง |
| --- | --- |
| Recall@5 | พบ A และ B ใน 5 อันดับแรก จึงได้ 2/2 หรือ 1.0 ถ้าพบแค่ A จะได้ 0.5 |
| Hit@5 | ได้ 1 เมื่อพบอย่างน้อยหนึ่งมาตราอ้างอิงใน 5 อันดับแรก ตัวอย่างนี้ได้ 1 |
| nDCG@5 | ให้คะแนนมากกว่าเมื่อมาตราอ้างอิงอยู่ต้นรายการ แล้วหารด้วยคะแนนของลำดับที่ดีที่สุด ตัวอย่างนี้ได้ประมาณ 0.65 เพราะ A และ B อยู่ลำดับ 2 และ 4 |
| RR@10 และ MRR@10 | ข้อนี้มีมาตราอ้างอิงแรกที่อันดับ 2 จึงได้ RR เท่ากับ 1/2 ถ้าไม่พบใน 10 อันดับจะได้ 0 ส่วน MRR คือค่าเฉลี่ย RR ข้ามข้อ |

รายงานหลักเฉลี่ยคะแนนทีละคำถามและให้น้ำหนักแต่ละข้อเท่ากัน ชุดอ้างอิงอาจกำกับมาตราไว้ไม่ครบ มาตราอื่นที่ช่วยตอบได้จึงอาจไม่ถูกนับในคะแนน

เปิด `retrieval_summary.csv` เพื่อดูคะแนนรวมและเวลา ดูอันดับจริงของแต่ละข้อใน `retrieval_rows.jsonl` หากต้องการเทียบกับคุณภาพคำตอบ ให้เปิด `retrieval_on_generation_subset.csv` ซึ่งใช้เฉพาะข้อที่เลือกไว้สำหรับสร้างคำตอบ ตัวเลข `index_seconds` คือเวลาสร้างตัวแทนตัวบทตามวิธีนั้น ส่วน `query_ms_per_question` คือเวลาเฉลี่ยต่อคำถามในการแปลงคำถามและจัดอันดับ โดยเวลาตัดคำร่วมของ R1–R3 อยู่ใน `shared_tokenize_seconds` ใน manifest

## อ่านผลการสร้างคำตอบ

| สิ่งที่อยากรู้ | เปิดดู |
| --- | --- |
| มาตราอ้างอิงอยู่ในผลค้นหรือหลุดตอนจัดตัวบท | `evidence_stages.csv` มี `retrieval_miss`, `context_omitted` และ `gold_in_prompt` |
| เจอหลักฐานของแต่ละข้อครบเท่าใด | `generation_rows.jsonl` ที่คอลัมน์ `context_recall` ซึ่งหารจำนวนมาตราอ้างอิงที่ส่งเข้าโมเดลด้วยจำนวนมาตราอ้างอิงทั้งหมด |
| คำตอบอ้างรหัสที่ส่งให้โมเดลบ่อยแค่ไหน | `generation_summary.csv` ที่ `citation_validity` หารจำนวนรหัสอ้างอิงที่อยู่ในชุดตัวบทด้วยจำนวนรหัสที่พบในคำตอบ ถ้าไม่มีรหัสเลย ช่องนี้จะว่าง |
| คำตอบถูกและตัวบทที่อ้างรองรับจริงหรือไม่ | ให้คนตรวจด้วย `review_template.csv` แล้วอ่าน `human_summary.csv` |

ตาราง `evidence_stages.csv` แยกว่ามาตราอ้างอิงหายไปที่ขั้นไหน

- `retrieval_miss` ห้าอันดับแรกไม่มีมาตราอ้างอิงเลย
- `context_omitted` ห้าอันดับแรกมีมาตราอ้างอิง แต่ไม่ได้ส่งมาตราอ้างอิงใดให้โมเดลหลังจัดงบ token
- `gold_in_prompt` มีมาตราอ้างอิงอย่างน้อยหนึ่งมาตราในชุดที่ส่งให้โมเดล ถ้าคำถามมีหลายมาตรา ให้ดู `context_recall` เพิ่มเพื่อแยกว่าได้ครบหรือได้เพียงบางส่วน

## ให้คนตรวจคำตอบ

1. เปิด `review_template.csv` จากรอบที่สร้างคำตอบเสร็จ ไฟล์นี้สลับแถวและซ่อนชื่อวิธีค้น
2. อ่านคำถาม คำตอบอ้างอิง คำตอบที่โมเดลสร้าง และตัวบทที่แนบมา จากนั้นกรอกสามช่องด้านล่าง
3. บันทึกเป็น `review_scored.csv` ในโฟลเดอร์ผลเดิม ใช้ UTF-8 และคง `review_id` ทุกแถวที่ส่งกลับ
4. เรียก `thai-legal-rag review` ด้วยชื่อโฟลเดอร์ของรอบนั้น

| ช่อง | ให้คะแนน |
| --- | --- |
| `coverage` | 0 เมื่อพลาดสาระสำคัญ, 1 เมื่อถูกบางส่วนหรือขาดเงื่อนไข, 2 เมื่อตอบถูกและครบ |
| `contradiction` | 1 เมื่อคำตอบขัดกับคำตอบอ้างอิงหรือตัวบทที่ใช้ตรวจ, 0 เมื่อไม่พบข้อขัดแย้ง |
| `citation_support` | 1 เมื่อตัวบทที่อ้างรองรับข้อความที่อ้าง, 0 เมื่อมีการอ้างแต่ตัวบทไม่รองรับ หากไม่มีการอ้าง ให้เว้นช่องนี้และจดไว้ใน `note` |

```bash
thai-legal-rag review rag_results/pilot_YYYYMMDD_HHMMSS_MICROSECONDS
thai-legal-rag review rag_results/pilot_YYYYMMDD_HHMMSS_MICROSECONDS --scores /path/to/review_scored.csv
```

แทนชื่อในตัวอย่างด้วยโฟลเดอร์จริง ระบบคิดคะแนนรวมเฉพาะข้อที่ทุกวิธีมีคะแนนครบทั้งสามช่อง เพื่อให้แต่ละวิธีถูกเทียบด้วยคำถามชุดเดียวกัน ถ้าเว้นคะแนนหรือยังตรวจไม่ครบ ข้อนั้นจะไม่อยู่ในตารางหลัก ดูจำนวนที่นำมาคิดจริงใน `reviewed_answers` เทียบกับ `answers` หากไม่มีข้อครบ ไฟล์สรุปจะมีเฉพาะหัวตาราง

## เก็บผลสำหรับเปิดดูภายหลัง

ผลแต่ละรอบอยู่ใน `rag_results/` หรือตำแหน่งที่กำหนดด้วย `--output-dir` เมื่อรันสำเร็จจะมี ZIP อยู่ข้างโฟลเดอร์ ถ้ารันสะดุด ให้เปิด `manifest.json` ดูขั้นที่เสร็จแล้วและข้อความ `error` หลังนำเข้าคะแนนที่ถูกต้อง คำสั่ง review จะเขียน `human_summary.csv` และ `human_evidence_stages.csv` แล้วอัปเดต ZIP แม้ผลสรุปจะมีเพียงหัวตาราง
