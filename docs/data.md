# ข้อมูลและการจับคู่มาตรา

## ชุดข้อมูลที่ใช้

| ชุด | ส่วนที่โหลด | ใช้ทำอะไร |
| --- | --- | --- |
| [VISAI-AI/nitibench-statute](https://huggingface.co/datasets/VISAI-AI/nitibench-statute) | `ccl` | คลังตัวบทที่ทุกวิธีใช้ค้น |
| [airesearch/WangchanX-Legal-ThaiCCL-RAG](https://huggingface.co/datasets/airesearch/WangchanX-Legal-ThaiCCL-RAG) | `train` | คำถาม คำตอบอ้างอิง และมาตราสำหรับลองรันแบบ `pilot` |
| [VISAI-AI/nitibench](https://huggingface.co/datasets/VISAI-AI/nitibench) | `ccl` | ชุดคำถามสำหรับวัดผลแบบ `test` |

คำสั่งทดลองโหลดทั้งสามชุดเพื่อตรวจรูปแบบข้อมูลและตรวจคำถามซ้ำข้ามชุด ส่วนหน้าเว็บใช้แค่คลังตัวบทในการสร้างดัชนี รุ่นที่ใช้จริงบันทึกเป็น SHA ใน `manifest.json` ของรอบรันหรือของดัชนี

## หน่วยที่ค้นและรหัสของมาตรา

หนึ่งแถวในคลังเป็นหนึ่งรายการค้น โปรแกรมกำหนดรหัสจากลำดับแถว เช่น `S00001` รหัสนี้ใช้ตามตัวบทระหว่างการค้น การสร้างคำตอบ และการตรวจผล เมื่อต้องเทียบรหัสระหว่างสองรอบ ให้ดูรุ่นคลังใน manifest ด้วย รหัสอาจเปลี่ยนเมื่อคลังเปลี่ยนหรือลำดับแถวต่างกัน

โปรแกรมเก็บตัวบทเดิมไว้แสดงในเว็บและส่งให้โมเดล สำหรับการค้นและจับคู่จะจัดรูปข้อความอีกชุดหนึ่ง โดยปรับ Unicode เป็น NFC แปลงเลขไทยเป็นเลขอารบิก จัดช่องว่าง และลบอักขระ BOM ในคีย์จับคู่จะตัดช่องว่างจากชื่อกฎหมายและเลขมาตรา รวมถึงตัดคำว่า “มาตรา” ที่ขึ้นต้นเลขมาตรา เช่น `มาตรา ๑๕` จะได้คีย์เลข `15`

## จับคู่มาตราอ้างอิง

ชุดคำถามกำกับมาตราที่ใช้ตอบไว้ เอกสารผลรันเรียกมาตราเหล่านี้ว่า `gold` โปรแกรมอ่าน `positive_contexts` จาก pilot และ `relevant_laws` จาก test แล้วจับคู่กับคลังตามขั้นตอนนี้

1. ใช้ชื่อกฎหมายและเลขมาตราที่จัดรูปแล้วค้นหารายการที่ตรงกัน
2. ถ้ามีหนึ่งรายการ ให้ใช้รหัสนั้นและบันทึก `matched_key`
3. ถ้ามีหลายรายการ ให้เทียบตัวบทที่จัดรูปแล้ว ถ้าตรงเพียงรายการเดียวให้บันทึก `matched_text` ถ้ายังเลือกไม่ได้ให้บันทึก `ambiguous`
4. ถ้าค้นตามชื่อกฎหมายและเลขมาตราแล้วไม่พบ ให้บันทึก `unmatched`
5. คำถามจะใช้คำนวณคะแนนเมื่อมีมาตราอ้างอิงและจับคู่ครบทุกมาตรา รหัสซ้ำในคำถามเดียวกันนับเป็นหนึ่งมาตรา

คำถาม pilot ที่ตรงกับข้อความ test หลังจัดรูปจะถูกกันออก โปรแกรมตรวจข้อความที่ตรงกันทั้งหมด จึงยังอาจเหลือคำถามที่เขียนใหม่แต่ถามเรื่องเดียวกัน

## ตรวจจากไฟล์อะไร

| ไฟล์ | ใช้ตอบคำถาม |
| --- | --- |
| `statute_ids.csv` | รหัสในผลรันตรงกับกฎหมายและเลขมาตราอะไร |
| `duplicate_keys.jsonl` | ชื่อกฎหมายและเลขมาตราคู่ใดพบมากกว่าหนึ่งรายการ |
| `question_audit.csv` | แต่ละข้อถูกเลือกหรือกันออกเพราะอะไร ดูคอลัมน์ `reason` |
| `mapping_audit.csv` | มาตราใดของคำถามจับคู่ไม่ได้ หรือมีหลายรายการให้เลือก |
| `manifest.json` | ใช้ข้อมูลรุ่นใด และข้อไหนถูกนำไปรันจริง |

เหตุผล `included` ใน `question_audit.csv` หมายถึงข้อนั้นผ่านเกณฑ์ ข้อที่ถูกนำไปรันจริงให้ดู `question_ids` ใน manifest โดยเฉพาะ pilot ที่เลือกตามจำนวนที่กำหนด
