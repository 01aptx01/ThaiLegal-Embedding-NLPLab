# หน้าเว็บและ API

เปิดเว็บจากคำสั่งใน [คู่มือเริ่มใช้งาน](getting-started.md#เปิดหน้าเว็บบนเครื่อง) FastAPI เสิร์ฟทั้งไฟล์หน้าเว็บและ API จากที่อยู่เดียวกัน ส่วน TypeScript ใน `frontend/` จัดหน้าจอและทยอยแสดงผลเมื่อข้อมูลมาถึง

## ใช้แต่ละหน้า

| หน้า | ใช้อย่างไร |
| --- | --- |
| Playground | พิมพ์คำถาม เลือกวิธีค้น แล้วเปิดรายการหลักฐาน ถ้าเซิร์ฟเวอร์เปิด Typhoon คำตอบจะทยอยขึ้นและกดรหัสมาตราในคำตอบได้ |
| Compare | เลือกหลายวิธีสำหรับคำถามเดียวกัน เปิดตัวเลือกสร้างคำตอบเมื่ออยากเทียบทั้งหลักฐานและคำตอบ ตารางเปรียบเทียบแสดงมาตราและเวลา |
| Evaluate | อ่าน `retrieval_summary.csv` จากโฟลเดอร์ที่ระบุด้วย `--evaluation-run` โดยดูชื่อรอบจาก manifest ถ้ามี |
| History | ดูคำถามที่เพิ่งรันในแท็บนี้และล้างรายการได้ ประวัติหายเมื่อรีเฟรชหรือปิดหน้า |

เมื่อใช้ `serve --retrieval-only` เว็บจะแสดงเฉพาะผลค้น เมื่อดัชนีสร้างด้วย `--no-dense` หน้าเว็บจะเปิดให้ใช้สามวิธีและปิดตัวเลือก BGE-M3

## เรียก API จาก Terminal

| ปลายทาง | ใช้ทำอะไร |
| --- | --- |
| `GET /api/status` | ดูว่าดัชนีพร้อมหรือยัง มีวิธีค้นใด ขนาดคลัง และรุ่นคลังหรือโมเดล |
| `POST /api/infer` | ส่งคำถามและวิธีค้นที่ต้องการรับผล |
| `GET /api/evaluate` | อ่านแถวจากผลทดลองที่ตั้งค่าไว้ คืนรายการว่างเมื่อยังไม่ได้ระบุโฟลเดอร์ |

ตัวอย่างนี้ใช้ shell แบบ Bash และรันได้กับเซิร์ฟเวอร์ที่เปิดเฉพาะการค้น

```bash
curl -N http://127.0.0.1:8000/api/infer \
  -H 'Content-Type: application/json' \
  -d '{"question":"บุคคลบรรลุนิติภาวะเมื่ออายุเท่าใด","methods":["r1","r2"],"generate":false}'
```

`methods` รับรายการรหัส `r1` ถึง `r4` จำนวน 1–4 รายการ โดยใช้ได้เฉพาะวิธีที่ `/api/status` ระบุ ห้ามซ้ำกัน คำถามยาวได้สูงสุด 1,500 ตัวอักษร ส่ง `"generate": true` เมื่อเซิร์ฟเวอร์เปิดโมเดลตอบคำถาม

## อ่านผลที่ทยอยส่งกลับ

ผลของ `/api/infer` เป็น NDJSON หรือ JSON หนึ่งรายการต่อหนึ่งบรรทัด เมื่อส่งหลายวิธี เซิร์ฟเวอร์ทำตามลำดับที่ส่งมา

| ค่า `type` | ข้อมูลที่ส่ง |
| --- | --- |
| `retrieval` | ผลค้นสูงสุด 10 มาตรา พร้อมรหัส ชื่อกฎหมาย เลขมาตรา ตัวบท และเวลาค้น |
| `delta` | ข้อความส่วนที่เพิ่งสร้างจากวิธีนั้น |
| `result` | คำตอบฉบับเต็ม รหัสที่ส่งเข้าโมเดล รหัสที่ข้าม รหัสที่อ้าง และเวลา ถ้าขอเฉพาะการค้น ค่า `answer` จะเป็น `null` |
| `error` | ข้อความผิดพลาดระหว่างส่งผล บางกรณีระบุวิธีที่เกิดปัญหา |
| `done` | ส่งผลของคำขอนี้ครบแล้ว |

หากต้องการแยกว่าคำตอบขาดหลักฐานตรงไหน ให้เทียบ `retrieved_ids` กับ `prompt_ids` และ `omitted_ids` ตัวอย่างเช่น มาตราที่อยู่ใน `retrieved_ids` อันดับ 6–10 ยังไม่อยู่ในชุด 5 อันดับที่นำมาลองใส่คำสั่ง ส่วน `omitted_ids` หมายถึงมาตราในชุดที่ลองใส่แล้วเกินงบ token

## แก้หน้าเว็บและทดสอบ

รัน backend บนพอร์ต 8000 จากราก repo ตามคู่มือเริ่มใช้งาน จากอีก terminal ให้เปิด Vite เพื่อแก้หน้าเว็บและดูผลทันที

```bash
cd frontend
npm ci
npm run dev
```

Vite ส่งคำขอ `/api` ไปที่ `127.0.0.1:8000` ตาม [vite.config.ts](../frontend/vite.config.ts) เมื่อแก้เสร็จให้รัน `npm run build` เพื่อให้คำสั่ง `serve` อ่านไฟล์จาก `frontend/dist`

เซิร์ฟเวอร์เปิดที่ `127.0.0.1` เป็นค่าเริ่มต้น และให้ประมวลผลคำขอ inference ทีละหนึ่งคำขอเพื่อจำกัดหน่วยความจำ หน้าเว็บเดิมใช้เป็นแบบอ้างอิงหน้าตา คู่มือนี้ใช้กับเว็บที่เปิดจาก repo บนเครื่องที่รัน Python
